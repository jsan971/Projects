Project 1 Proposal - Task Tracker
App Name : doit
App Description: The purpose of this application is to track user tasks through a terminal (command line interface). The application is designed for a single user to organize and track tasks.
Storage Solution : The application will use a local .txt file for persistent storage. When the application is started, it will load existing tasks. Such modifications like adding, removing, deleting a task will update the applications memory and append these changes into the storage file txt. This will help prevent data loss for when the application is closed or terminated. 
Core Features: 
* Create, Read, Update and Delete (CRUD)
* Persistent  storage via local txt file to add/modify changes automatically this prevents data loss such the application is terminated abruptly 
* Task Status (Pending, In Progress, Complete) - Allow the user to add or modify a task’s status. 
* Clear all tasks - Provide the ability to wipe all tasks within the application and resetting the tasks.txt 
* Color Coded Console Output. Given this is a terminal based application, readability is important. Status will have specific colors assigned when viewing/displaying the list of tasks that include a status. 
   * Pending = Blue
   * In Progress = Green
   * Complete = Red
Stretch Features:  
* Due Dates - Allow the user to add specific due dates for new and existing tasks
* Filtering - Allow the user to filter based on the tasks that have a set status which are pending, completed or in progress.




Main Classes / Modules : 
Core class 1 : Task
* This will contain attributes about the overall project and its scope. Minimal logic in this core class called Task.
Class 2 : Manager (manages the CRUD operations) 
* This will handle the majority of the core features of the application and persisting our storage to a local txt file such that there are any changes to the tasks.
Class 3: Handling the CLI interface / display menus
* This class will handle the interaction between the user and displaying output to the console.
* The input provided from user will also be passed to our Manager class
Module : TaskValidator 
* This module will provide reusable methods for the input validation from the user for our core features.
